MethodInfo vs Linq Expressions for Hot Chocolate GraphQL Server

Apr 8, 2025 • Ian Grainger

We needed to modify how the C# GraphQL server we were using (Hot Chocolate) performs searches in a couple of ways.

The first was quite straightforward - we needed to make our text searches (using the contains operator) case insensitive. That is actually given as an example in the docs. This example shows how to use the Configure method of a class derived from FilterConvention, and calling AddFieldHandler with a class derived from QueryableStringInvariantContainsHandler.

But we also wanted to allow partial case insensitive search on a Guid field - with or without hyphens. This would mean adding the 'contains' operation to GraphQL's UUID type and using a more complicated expression to perform the search.

Note: Most of the credit here is owed to Harrison Pitcher at GMSL who worked most of this out - particularly how to use AddProviderExtension and ReflectionUtils

1. Adding the contains operation for a Guid field

The example linked above shows how to provide a string operation filter. To add a new operation to a field of any type, you need to go up a level and implement the QueryableOperationHandlerBase class. You can then override CanHandle to show what operations can be handled, and HandleOperation to do the work of creating the expression to be run when the handled operation is performed via GraphQL.

Once we had got access to all the MethodInfos we needed, and chained them with Expression.Call to give the resulting expression tree - we could connect that to the GraphQL server like this: 

// In service start up
builder.Services.AddGraphQLServer().AddConvention<IFilterConvention>(
  new FilterConventionExtension(
    filterConventionDescriptor =>
    {
      filterConventionDescriptor.Configure<UuidOperationFilterInputType>(
        filterInputTypeDescriptor =>
          filterInputTypeDescriptor.Operation(DefaultFilterOperations.Contains).Type<StringType>());

      filterConventionDescriptor.AddProviderExtension(
        new QueryableFilterProviderExtension(filterProviderDescriptor =>
          filterProviderDescriptor =>
            filterProviderDescriptor.AddFieldHandler<QueryableUuidContainsHandler>()));
    }
  ));
// End service start up
          
public class QueryableUuidContainsHandler : QueryableOperationHandlerBase
{
  private static readonly MethodInfo GuidToStringMethodInfo = 
    ReflectionUtils.ExtractMethod<Guid>(x => x.ToString());

  private static readonly MethodInfo ReplaceMethodInfo =
    ReflectionUtils.ExtractMethod<string>(x => x.Replace(default(string)!, default!));
      
  private static readonly MethodInfo ToLowerMethodInfo =
    ReflectionUtils.ExtractMethod<string>(x => x.ToLowerInvariant());

    public override bool CanHandle(
      ITypeCompletionContext context,
      IFilterInputTypeDefinition typeDefinition,
      IFilterFieldDefinition fieldDefinition)
    {
      return context.Type is UuidOperationFilterInputType;
    }

  public override HandleOperation(
    QueryableFilterContext context,
    IFilterOperationField field,
    IValueNode value,
    object? parsedValue) {
    
    var property = context.GetInstance();
    
    parsedString = parsedValue switch {
      Guid guidValue => guidValue.ToString(),
      string stringValue => stringValue,
      // ... (null and default handling)

    }

    var doToString = Expression.Call(property, GuidToStringMethodInfo);
    var doToLower = Expression.Call(doToString, ToLowerMethodInfo);
    var doRemoveDashes = Expression.Call(
        doToLower,
        ReplaceMethodInfo,
        Expression.Constant("-"),
        Expression.Constant(string.Empty));
    
    var lowercaseParsedString = parsedString.ToLowerInvariant();

    var dashedContains = FilterExpressionBuilder.Contains(doToLower, lowercaseParsedString);
    var undashedContains = FilterExpressionBuilder.Contains(doRemoveDashes, lowercaseParsedString);

    return Expression.Or(dashedContains, undashedContains);
  }
}

2. Moving from Expression.Call on MethodInfos to Expression.Invoke on Expression<Func<T, Y>>

Now our new contains filter was working - but the code didn't look good. There was a lot of lines finding MethodInfos in order to construct the expression to execute when GraphQL was performing the filter. And unfortunately the way you go about finding them (matching number of parameters etc) is complicated and hard to read.

A senior developer suggested that it should be possible to use a LINQ expression instead. That means creating a LINQ delegate, but casting it to Expression, so it will be an object of type Expression<Func<T, Y>>.

What confused us for a while was that while you can use Expression.Call to execute a method - a LINQ expression requires you to use Expression.Invoke, passing in the expression itself and any runtime arguments.

This meant that we could write our more complex expression in a single line of LINQ, which makes it much easier to read! 

public class QueryableUuidContainsHandler : QueryableOperationHandlerBase
{
  private static readonly Expression<Func<Guid, string, bool>> UuidContainsExpression = 
    (fieldValue, queryValue) =>
        fieldValue
        .ToString()
        .Replace("-", string.Empty)
        .Contains(queryValue, StringComparison.InvariantCultureIgnoreCase)
      || fieldValue
        .ToString()
        .Contains(queryValue, StringComparison.InvariantCultureIgnoreCase);
        
  public override HandleOperation(QueryableFilterContext context, IFilterOperationField field, IValueNode value, object? parsedValue) {
    var property = context.GetInstance();
    
    parsedString = parsedValue switch {
      Guid guidValue => guidValue.ToString(),
      string stringValue => stringValue,
      // ... (null and default handling)

    }

    return Expression.Invoke(UuidContainsExpression, property, Expression.Constant(parsedString))
  }
}
